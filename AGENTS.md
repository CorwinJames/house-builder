# House Builder — notes for AI assistants

> **Before every session, pull the latest from `main` (git pull) before making changes, and push or open a PR when you finish, so different assistants don't overwrite each other's work. Never start work on a stale checkout.**

This applies to every assistant that touches the repo: Grok Build, Claude, Cursor, Grok Bot, and anyone else. Read this file before editing.

## What this is

A personal, static house planner for James Corwin and his wife Sophie. They are designing one hempcrete house in Jefferson County, Washington. It is not a general CAD product. Features get added as they experiment.

The long-term feeling is a simple building game: drag walls and rooms, and the app fills in real assemblies, routes wire and pipe, prices a materials list from cited sources, and warns against cited code rules. The output should eventually be drawings an engineer can stamp. Stage 2 is drag-to-build. Stage 4 prices the list from cited sources. Stage 5 places electrical devices and routes circuits. Stage 6 places fixtures and routes supply and drain piping. Stage 7 checks the drawing against cited code rules. Stage 8 makes the parcel the level: setbacks, a well, a septic field, and a pad. Assembly thicknesses are still placeholders with no invented code citations.

There is no server. The site is a static build deployed to GitHub Pages.

**Never invent a price.** A cost line needs a published price, a published wage, a bid, or a user entry. If you cannot find one, leave the amount empty, mark the line "price needed", and keep it out of the total. Every price record in `data/prices.json` needs a source name, a URL when it has a dollar amount, the date it was checked, a unit, and whether it is labor or material. To add or refresh a price, edit that file and re-read the page. Do not copy a number from memory. Production rates in `data/cost-assumptions.json` that are not from a published source must say they are assumptions. A bid or user entry on the house `cost.overrides` replaces the published amount.

## Architecture

Plain ES modules and [Vite](https://vitejs.dev/). Three.js draws the model. There is no React and no backend.

- `index.html` mounts `#app`.
- `src/main.js` builds the screen, owns view state, and talks to both renderers.
- `src/render/plan2d.js` draws the plan on a canvas. North is up.
- `src/render/view3d.js` draws the model. Plan +x (east) is Three.js +X. Plan +y (north) is Three.js −Z. Height is Three.js +Y.
- `src/render/roof.js` builds the placeholder roof shape.
- `src/layers.js` is the list of layer toggles.
- `src/state/viewState.js` reads and writes `localStorage` key `house-builder.view.v1` (camera, layers, phase).
- `src/ui/editor.js` is Build mode. The tool bar and the options for the active tool sit on the plan. Undo and redo are there too. Export, import, and reset are in the File menu. The house document is `localStorage` key `house-builder.document.v2`. There is no Pan tool: drag empty space, hold Space, or use the middle or right button.
- `config/google.json` holds the public Google OAuth client ID for project `house-builder-514402`. There is no client secret. The Cloud app is in Testing, so only invited testers can sign in, and consent can expire after about 7 days.
- `src/auth/google.js` uses Google Identity Services `initTokenClient` in the browser. The only scope is `https://www.googleapis.com/auth/drive.file`. The access token is kept in `localStorage` (`house-builder.google.token.v1`) until it expires, about an hour, so a reload reopens the Drive plan with no popup. After that, reconnecting passes the last account as `login_hint`, so it is one click. Sign out clears the token and the hint. There is no refresh token, because that needs a server.
- `src/drive/client.js` talks to Drive API v3 with `fetch`. `scripts/test-drive.mjs` mocks `fetch`, so CI does not need Google credentials.
- `src/ui/account.js` is the header account control and the Drive actions in the File menu. A signed-in open file autosaves about 10 seconds after the last edit. When Google needs a click, a small "Reconnect Drive" pill sits in the top bar (there is no banner). If edits were made on this device while Drive was waiting, reconnecting saves them to the Drive file, and the modified-time check still asks before it overwrites a newer copy.
- Screen layout: the plan and 3D fill the window under a slim top bar. The layer panel, the selection card, the view toolbars, and the build dock all float on top as glass (`.glass`), so nothing that opens, closes, or changes text resizes the drawing. New plan, Open, and Save are in the File menu. The Guide and Recent list open from the Guide pill in the build dock. The layer panel collapses with its Layers button (`panelCollapsed` in view state).
- The camera never moves because of an edit. `frameBuildIfNeeded` in `src/main.js` only frames again for a different plan (New plan, Open, Import). Fit and Reset view still frame on request.
- The **Scale** tool (`src/build/scaleFigures.js`) drops a person (5 ft 9 in), a queen bed (60 × 80 in), a sofa, a table for six, or a car, to judge size. They are stored as `furniture` records with a note that they are scale figures, so they move, copy, and delete like furniture, draw in plan and 3D, and stay out of the cost.
- **Walk** in the 3D toolbar puts the camera at eye height (5 ft 6 in) in the selected room, or the biggest room. W A S D or the arrows walk, Shift is faster, drag looks, Esc or Walk exits and restores the orbit camera. Touch screens get an on-screen pad. Walls do not block you. Labels hide while walking. The plan shows a "You" dot with a view cone while you walk; drag it to stand somewhere else. On a wide screen, walking from 3D-only opens Split so the plan is visible, and leaving puts the view back. The 3D camera ignores frame and fit calls while walking. Code is in `src/render/view3d.js` (`setWalking`, `setWalkPosition`) and `src/render/plan2d.js` (`setWalker`).
- `src/build/joins.js` works out where wall faces meet, for drawing only: L corners miter, a wall that tees in stops at the other wall's face, and a straight run stays square. The plan strokes every wall outline first and fills on top, so walls that touch read as one shape. The 3D view uses the same outlines for the wall ends. Cost still reads the centerlines.
- `src/build/` is snapping, wall joins, room detection, and opening placement. No DOM.
- `src/rules/` is the warning list. Geometry checks and the code rules both come out of `evaluateRules`. The header badge, the list, and the plan markers read that one list.
- `data/sample-house.json` is the house. Renderers do not hard-code room sizes.
- `data/assemblies.json` defines wall types. `data/headers.json` is the placeholder header table. `data/opening-catalog.json` is the door and window palette.
- **Clip on or lay on** (`src/build/clips.js`, schema 8 `joins`). Walls whose ends touch are either clipped (listed together in `house.joins`, they move as one) or laid on (not listed: they touch and draw as one corner, but each moves on its own). The build dock has a Lay on / Clip on switch, Lay on by default; holding Option flips it for one drag. It decides what happens when a dropped wall end, a moved wall, a group, a new wall, or a new room touches another wall. It also decides what dragging a whole wall (or a group) does to its clips: with Lay on the dragged walls let go of walls outside the drag (`detachWalls`), and the toast offers "Keep it clipped"; with Clip on, clipped neighbours stretch along. Dragging an end handle follows the same rule: with Lay on only that wall's end moves and it comes off the corner; with Clip on or Option the clipped corner moves with it. End handles are grabbed only within about 11 screen pixels of the dot, so the rest of a short wall drags the whole wall. Option is read from the pointer event itself (`clipping(event)`), so a missed key-up can't leave it stuck. The floating length label does not catch clicks (it sat over other walls and swallowed them); type a length on the wall card, or press Tab while drawing. A dropped end with Clip on clips only that end (`clipVersion(..., { endOnly: true })`); the wall's other end keeps what it had. Moving a whole wall or group still clips every end that touches. Clipping onto a spot joins one piece there (`clipToOne`): an existing clipped piece if there is one, otherwise the newest wall, so walls that were only laid on each other there stay separate. The wall card has "Detach this wall". Only Clip on cuts a wall that something tees into. The toast after a touching drop offers the other choice as one step. The wall card lists each end (clipped, laid on, free) with Unclip / Clip on. Selected wall end handles are solid green when clipped and clay when laid on. A room's own four corners are always clipped. Files saved before schema 8 have no `joins`, so `decorateHouse` infers them from ends that touch (within 0.25 ft), which keeps old plans behaving as before. Tidy up shape still moves every touching corner. `moveEnd` and `translateWalls` in `src/build/walls.js` follow the clips.
- Selection cards (`paintInspector` in `src/ui/editor.js`): the **wall** card starts with the material, then Length, Angle, and Height as typed tiles (Enter or click away applies; the angle explainer hides behind a "?"), the ends, Phase and Wiring, and a folded Cost list. The **room** card's name is the title and can be typed in, then Area and inside sizes, Shape chips, Fill this room (suggest outlets or a sink), Phase, a folded Issues and tips list, and a folded Cost list. Explainer and placeholder text stays out of the cards.
- **Sun and shade** (`src/sun/`, `src/render/sun3d.js`). A layer, off by default. `src/sun/solar.js` is the NOAA sun position (azimuth clockwise from north, elevation) and `currentSun(house, settings)`: when the plan has a real lot (`site.parcel.origin` and not `site.sample`), or else a reference place (`house.solar.place`, see `sunPlace`), the sun comes from that latitude and longitude, a date and a Pacific clock time; otherwise, or with "By hand", from a typed direction and height. `SEASONS` holds the four season buttons (Dec 21, Mar 20, Jun 21, Sep 22, cited to Griffith Observatory); a plan with no place gets a place search in the Sun panel that sets `house.solar.place` through `editor.setSolarPlace`. Settings live in view state as `state.sun`. `src/sun/light.js` (no DOM) works out floor patches, wall and roof ground shadows (`wallShadows`, `roofShadows`), and how much of each room is sunlit. A window patch is traced along straight sun lines: every half foot along the opening, `litRange` in `src/sun/rays.js` finds which heights on the outer wall face see the sun past the real roof surface (`roofSurfaceAt` per footprint: eaves, gable rakes, hips, curves), awning plates (their real width), other buildings, and walls in the way. That outline, dropped to the floor, is clipped by the opening at the inner face (`clipConvex`), so thick walls narrow the patch at an angle. `roofShadows` is the convex hull of the roof surface pushed along the sun, plus the walls box. Windows, sliding and cased doors let sun in; swing doors don't. The plan draws shade over roofed rooms and wall shadows through one mask, then warm patches clipped to each room, and a sun marker on a ring that can be dragged in By hand. The 3D view moves its one shadow-casting light to the sun, warmer and dimmer when low, drops the sky fill, adds invisible shadow-only full-height walls and ceilings plus a copy of the drawn roof (`syncRoof`, sharing its geometry; skylight openings are cut out of its shadow by a depth-material shader, up to 24) so Cutaway and roof-off still shade the rooms and ground shadows match the roof. The shadow camera is fitted to the casters' bounding sphere and uses a 4096 map when the graphics card allows, and gives up to six sunlit rooms a soft warm bounce light. **Skylights** (`src/build/skylights.js`, `house.skylights`: `{ id, x, y, model, width, depth, rotation, roomId? }`, optional in schema 8) are real VELUX FS deck-mount sizes (C01, C04, C06, M02, M04, M06, S06, by published rough opening). The Skylight tool drops one into a roofed room; it sits on the roof face above, the long way down the slope, and `refreshSkylight` rewrites size, turn, and room after every move or paste. `src/build/roofShape.js` (no Three.js) gives the placeholder roof's height, face, and slope at any plan point (`roofAt`), and `roofFootprints` moved there. `skylightBuild` works out the as-built skylight: straight vertical shaft from the ceiling (roof plate height) to the roof, ceiling opening = roof opening seen from above, four shaft walls with their heights, 2x4 at 16 in. o.c. with R-15 batts and 2 in. R-10 XPS on the attic side (WSEC-R 13+10) and 1/2 in. drywall, and the roof and ceiling openings framed per IRC R802.9 with rafters and joists assumed 24 in. o.c. (a 21 in. opening fits a bay; wider ones cut one and get a single header and doubled trimmers). Its problems (no room, no roof, pitch outside 14–85°, crosses a ridge or hip, runs into a wall) feed `src/rules/skylights.js`. The card shows the model chips, "How it's built", and its cost. Light: `skylightPatch` in `src/sun/light.js` lets sun in only when the sun is in front of the roof face, and each shaft wall trims the patch at its top and at the ceiling, so a deep shaft cuts off low sun. In 3D the shadow-only stand-ins add the shaft walls, ceiling holes, and a lid that closes the shaft when the sun is behind the roof; with the roof off the shaft draws as see-through drywall. Cost: `src/cost/skylights.js` adds a Skylights group (unit, flashing kit, shaft studs at the 2x4 price via `priceId`, batts, XPS, drywall, and rafter-size lumber, price needed until the roof is framed). The layer hides itself in Build mode unless "Keep on while building" is ticked. The Sun panel floats top right. It ignores trees, terrain, window frames and mullions, and light through a second window.
- **Passive solar** (`src/sun/passive.js`, `src/ui/solarPanel.js`, the **Solar** tool). Place = the lot, else `house.solar.place` (a reference place found with the Open-Meteo geocoder or typed as "lat, lon"). Climate = `house.solar.climate` (heating degree days at 65 °F and cooling at 75 °F from ten years of Open-Meteo daily means, looked up automatically for a new place) or `house.solar.climateChoice`. The overhang rule by climate: cold (>6,000 HDD) puts the Jun 21 noon shadow line at mid-window, moderate at the sill, hot (>2,600 CDD) at the sill on Mar 20; every climate wants the whole window in sun at Dec 21 noon. Shadow line = shade height − depth × tan(profile angle). `wallFacing` finds a wall's outside (heated rooms only; a covered patio is outside; later-phase rooms count only in Full house). `eaveAt` measures the roof edge past a wall face; `roof.eaves` (`{south, north, east, west}`, feet past the outer wall face, optional) replaces the old single overhang for both phases (`withEaves` in `src/build/roofShape.js`). Windows can carry an `awning` (`{depth, gap, extend}`: out from the face, above the window top, past each side), drawn in plan and 3D by `src/build/awnings.js`. The panel shows the place, climate, noon sun on Dec 21 / Mar 20 / Jun 21, a section through the chosen window with the eave, awning, and three noon rays, the sun-side eave range with a Set button, roof pitch buttons for solar collectors (latitude for hot water, +15° for space heating), each window by side with Dec/Jun noon status and an Awning button, and house checks (sun-side glass 7–12% of heated floor, other sides under 4%, long wall within 15° of south). Sun patches through windows now stop at the eave/awning shadow line, and in 3D the eaves and awnings are shadow casters. Plan north is taken as true north.
- **Roof tool and clerestory** (`src/build/clerestory.js`, `createClerestoryRoof` in `src/render/roof.js`). The Roof tool sets the shape (Hip and gable, or Clerestory), the pitch, and the four eaves (`roof.eaves`). `roof.clerestory = { face, setback, glass, eave, lowPitch }` turns the biggest roof into a low shed in front (its own pitch, default 3:12), a 1 ft curb, the glass band (mullions about every 4 ft), a 1 ft header, and a high shed behind whose pitch follows from those heights; gable ends close the sides. `roofAt` returns the low or high face, so skylights, eaves, and the sun use it. `clerestoryPatches` in `src/sun/light.js` lets sun through the band (shaded by the high roof's eave) onto the floor of every room it reaches, ignoring interior walls; in 3D the rooms under the high roof lose their flat ceiling caster (open to the roof) and the band's solid parts, the high roof (with skylight holes), and the gable ends cast instead. The tool shows where Dec 21 noon sun lands (floor or back wall) and an eave range for the band by the climate rule. `houseSolar` counts the band as glass on the side it faces.
- **Folding glass wall**: door style `folding` (palette "Folding glass wall 16'", or the Style row on the door card). About 3 ft panels (`foldingPanels`), drawn as a zigzag in plan and glass with mullions in 3D, counted as glass for the sun, costed per foot as `folding-glass-wall` (price needed). Openings over 16 ft get a "beam (size by engineer)" placeholder header. The 3D sun stand-ins now declare `full` before the eave casters use it (the passive-solar merge had them throw while the Sun layer was on).
- **Arranging like design software** (`src/build/transform.js`, the Arrange bar `#arrange-bar` and the selection frame in `src/ui/editor.js`, `drawFrame` in `src/render/plan2d.js`). With the Select tool, any selection of rooms, walls, and pieces gets a dashed frame with a round handle above it: drag the handle to turn (clicks onto 15° steps when within 3°; Shift for strict 15° steps), with the angle shown under the frame. The Arrange bar above the build dock names what moves together and has ⟲ 90° / ⟳ 90°, a "Turn °" box (counter-clockwise; minus for clockwise), Flip left-right, Flip top-bottom, and Duplicate. Keys: R turns 90° clockwise, Shift+R counter-clockwise, Shift+H / Shift+V flip, arrow keys nudge 1 in (Shift: 1 ft), ⌘/Ctrl+D duplicates beside the selection, ⌘/Ctrl+A selects everything visible, ⌘C/⌘V now copy rooms and walls too (paste centres at the pointer). `selectionSet` expands picks: a room brings its walls (`roomWallIds`: the old midpoint rule plus any wall running along a room edge), the furniture, skylights, labels, and site marks inside it, rooms drawn inside it, and its outlets and fixtures; a wall brings its openings. `separateSelection` first cuts a wall the room shares with a neighbour where the neighbour's wall tees in (only at boundaries between the room's stretch and the rest; short corner stubs stay with their neighbour), so turning, flipping, nudging, duplicating, or dragging one room takes only its own stretch. Turning and flipping let go of clips to walls outside the selection (the toast says how many). Flip mirrors door swings and furniture angles; skylights re-fit to the roof. Dragging a room or a group now carries its contents (`shiftContents`), and a group of pieces without walls drags as one. Tests: `scripts/test-transform.mjs`.
- **Templates and East Asian building parts** (`src/build/templates.js`, the **Templates** and **Column** tools, the Roof tool's per-building block). Twelve templates: China (three-bay hall, five-bay hall, siheyuan, sanheyuan, southern skywell house), Japan (minka with doma and four raised rooms, Kyoto machiya, shoin house with engawa), Korea (hanok ㅡ, ㄱ, ㄷ, ㅁ). Each is written as rooms on wall centerlines on its bay module (jian 11 ft, ken 6 ft, kan 8 ft, cited in the file), extra walls, doors and windows by room side, posts, and building settings; `wallSegments` works the walls out (a side one enclosed room owns is an outside wall in that building's outside assembly, a shared side is a partition in its inside assembly; covered and site rooms make no walls). The Templates tool shows small plans to pick from; a see-through ghost (`overlay.templateGhost`, `drawTemplateGhost`) follows the pointer, R turns it, it turns red over existing walls, and a click places ordinary walls (clipped at shared ends), rooms, doors, windows, posts, and `house.buildings` entries with fresh ids, then selects it all in the Select tool. Any closed space it makes but did not name becomes a site "Yard". New in schema 8 (all optional): `house.buildings[name] = { name, style, ridge, curve, platform, pitch, template }`, `house.columns = [{ id, x, y, size, shape, phase, building }]`, `room.floorLevel` (feet above grade), and `roof.style` / `roof.ridge` / `roof.curve`. **Roofs**: `roofFootprints` makes one roof per building whenever the plan separates site areas or any room names a building other than main; covered rooms that name a building (verandas, engawa) go under its roof. Forms: hip-and-gable (default), hip, gable (runs past the end walls, with wall triangles closing the ends), flush gable (ends cut at the wall face); ridge east-west (default, as before), north-south, or the long way; curve 0–1 sags the slopes and turns the eave corners up (`curveLift`), the same in 3D (`createRoofGeometry`) and in `roofAt`, so skylights and the sun follow it; each building can have its own pitch. The plan draws ridge and hip lines. A quarter turn of a selection swings its buildings' ridges; duplicating rooms of a named building makes a new building. **Platform**: `buildings[].platform` draws a stone plinth (`platformRect`) in plan and 3D; the Roof tool moves floors that sat on the old top to the new one. **Raised floors**: the room card's Floor height (chips and a typed tile); 3D draws the floor as a block up to that height; the plan label says "Floor up …". **Columns**: the Column tool places one post, or a row along a drag at a chosen spacing; posts draw in plan, run from a stone base up to the roof in 3D, select, move, turn, copy, and delete like other pieces, come along with a room whose edge they stand on, and go when their building's last room is deleted. **Wall types** added to `data/assemblies.json`: timber frame with earth infill (8 in), fired brick (12 in), sliding paper screens (2 in); render buckets `timber-infill`, `brick`, `screen`. **Bay grid**: More options → Snap step has Jian / Kan / Ken bays, drawn as their own grid. **Cost**: earth infill, brick, paper screens, posts and bases, raised floors, and platforms are new lines, all price needed (`data/prices.json`). Tests: `scripts/test-templates.mjs`. Not built: single-slope (shed) roofs of skywell houses, stepped horse-head gable walls, two-storey machiya, and roof ornaments.
- **Furnish tool** (`src/build/furnish.js`, `src/render/furnish3d.js`, `drawFurnishing` in `src/render/plan2d.js`). Sims-style real-size pieces: toilet, bathroom sink, shower, kitchen sink, stove, dishwasher, fridge, washing machine, dryer, wardrobe; sizes in inches from cited guides (`FURNISHINGS`, `FURNISH_SOURCES`). Pick one in the tool options; a ghost (`overlay.furnishGhost`, drawn in plan and 3D) follows the pointer and sits with its back to the nearest wall within reach, facing into the room (`furnishPose`); R turns it away from walls; click places it (Shift-click keeps it in hand, Esc puts it back). Stored as `furniture` with a `link` (schema 8, optional). Dragging snaps back to a wall. Plan draws a symbol per kind (bowl, basin, burners, drum, doors); 3D draws simple real-size shapes in the Finishes layer. **One object**: a toilet, sink, shower, dishwasher, or washer standing against a wall is also its plumbing fixture, and a stove or dryer its 240 V device; `syncFurnishings` (run in `commit`) makes, moves, and removes that point (`furnitureId` on the point, `link` on the piece), and a copy gets its own point. A fridge and a wardrobe have no point. Tests in `scripts/test-trace.mjs`.
- **Pictures and tracing** (`src/build/images.js`, `src/build/trace.js`, the **Pictures** layer). ⌘V of a picture or SVG from another app (Affinity Designer: PNG by default; with Settings → General → "Copy items as SVG" its vector lines come too), dropping an image file on the plan, or File → Add a picture… makes `house.images[]` `{ id, name, x, y, width, height, rotation, opacity, scaled, src (data URL, at most 1600 px, PNG unless large), pxWidth, pxHeight, lines? }` (schema 8, optional), drawn over the room colours and under the walls. In-app ⌘C writes a marker to the system clipboard so the next ⌘V pastes our own copy, not an older picture; browsers that send no paste event still get the in-app paste after 150 ms. A picture is clicked last (after walls, rooms, and pieces). Its card: width (keeps proportion), see-through, **Set the scale** (click two ends of a known length, type the real length; `rescaleImage`), and **Turn into walls** (Walls only / Walls and doors): SVG lines are used as they are (any angle, through transforms; curves skipped); otherwise `rasterSegments` finds straight strokes across and down the pixels (Otsu ink cut, strokes thicker than 2 ft skipped). `planFromSegments` squares near-square angles, merges a wall drawn as two lines (or a filled wall's edges, up to 1.6 ft apart) into one, joins pieces on one line, makes 1 ft 10 in–8 ft gaps doors (over 4 ft a cased opening), meets ends to the wall they stop at, cuts true crossings, and drops short loose bits (door leaves, labels). A blue preview shows first; Keep runs `addTracedPlan`: walls facing outside get the exterior type (rammed earth on a south face), others the partition; rooms come from room detection; all selected. If the browser store fills up, a toast says so instead of failing quietly (`saveLocal`). Tests: `scripts/test-trace.mjs`. Not done: curved walls, windows from a drawing, reading a scale bar or dimension text.
- **Resize and groups** (`scaleSelection` in `src/build/transform.js`, `src/build/groups.js`). The selection frame has four corner squares: drag one to make the selection bigger or smaller, keeping its proportions, with the opposite corner fixed (1% steps, Shift 5%; the label shows the percent and the new size). The Arrange bar's Size box takes "150%", "150", or a width like "40 ft". Walls get longer and rooms bigger, but wall thickness and height, door and window sizes (they keep their place along the wall, clamped to fit), furniture, fixtures, columns, and skylights keep their real size; pictures scale. Like turning, it lets go of clips outside the selection. **Groups**: `house.groups = [{ id, name, members: [{ type, id }] }]` (schema 8, optional; walls, rooms, columns, furniture, pictures, skylights, site marks, labels). A traced drawing (walls and rooms) and a placed template become a group. Clicking any member selects the whole group; clicking a member of the selected group again (without dragging) goes into the group, and its parts then select one at a time until you click outside it. The Arrange bar shows Group (two or more things picked) or Ungroup (a whole group picked). Duplicating a whole group makes a new group. `pruneGroups` (in `commit`) drops deleted members and groups left with one. The picture a drawing was traced from is not in the traced group. Tests in `scripts/test-trace.mjs`.
- **Lining up** (`src/build/align.js`, the second row of the Arrange bar). With two or more "units" selected, six buttons line them up: left edges, centres left to right, right edges, top edges (north), middles top to bottom, bottom edges. `selectionUnits` splits a selection into what moves as one: each group whole; rooms and walls that share a wall or touch at a wall end (a section of house); each other thing (a picture, furniture, a label). The unit holding the first thing picked stays still; the others slide straight across or straight up/down (`nudgeSelection`, after `separateSelection`), letting go of clips outside them like other arranging. Shift-click on a grouped thing now adds or removes its whole group. A picture can be picked by clicking right on its dashed outline (even over rooms) or by a box that takes it all in. The Arrange bar now sits above the build dock and any tip over it. Tests in `scripts/test-trace.mjs`.
- **Align snap** (`src/build/alignSnap.js`, the "Align snap" pill in the build dock, on by default, saved in `localStorage` `house-builder.alignSnap`; hold Ctrl or ⌘ to drag freely). While a resize corner is dragged (`snapScale`) or a wall end is dragged (`snapPoint`), the corner clicks onto the left, right, top, or bottom edge of anything shown (rooms with their walls, a room's inside outline, walls, pictures, furniture, columns, groups, and sections of rooms that share walls; `alignTargets`, worked out once per drag) within about 8 screen pixels, or to the same width or depth as one of them (a near-straight wall end: the same length). A wall end that already clicked onto another wall end keeps that. The plan draws pink guide lines, matching size spans with the length, and a dot on the snapped corner (`overlay.alignGuides`, `drawAlignGuides`); the toast after a resize says what it lined up with. Tests at the end of `scripts/test-trace.mjs`.
- **Door and window card** (`paintOpeningInspector`): Width, Height, Sill, Top (moving the top keeps the height), distance from either end of the wall, Center, the header room left on the wall, noon sun on the glass, and the awning. Edits that overlap, crowd a corner, sink below the floor, or leave no room for the header are refused with a toast.
- Hidden layers can't be clicked: the plan skips Site, Electrical, and Plumbing pieces when their layer is off (unless that layer's tool is active), and the 3D view ignores hidden objects when picking.
- `schemas/house.schema.json` is the contract for the house file. Schema versions 2 through 5 still open. The app writes version 6, which adds an optional `site` block. Version 5 added plumbing. Version 4 added electrical. Version 3 added cost. `schemas/materials-list.schema.json` is the export a later Materials Scout can read.
- `src/cost/` turns geometry into quantities and applies `data/prices.json`. `src/ui/costs.js` is the header total and the materials panel. Electrical quantities come from `src/electrical/`. Plumbing quantities come from `src/plumbing/`.
- `src/electrical/design.js` places devices, suggests receptacles, groups circuits, routes them, and builds the electrical rows. The plan draws those routes when the Electrical layer is on.
- `src/plumbing/design.js` places fixtures, suggests a bathroom or kitchen layout, routes supply and DWV, and builds the plumbing rows. The plan draws those routes when the Plumbing layer is on. Labels wait for hover or selection.
- `scripts/check-model.mjs` checks the sample against the schema. `scripts/test-geometry.mjs` checks snapping, joins, rooms, and openings.

The phase toggle and the Future wings layer both gate later rooms. Phase 1 only hides future geometry even if the layer is on. Full house hides it when the layer is off. See `src/render/visibility.js`.

The Site layer draws the parcel, setbacks, contours, the well, and the septic field. `scripts/fetch-parcel.mjs` can pull a Jefferson County lot by parcel number or address. The sample lot is a labeled 5 acre rectangle, not a real parcel. The Electrical layer draws devices and circuit routes. The Plumbing layer draws fixtures, supply, and drains.

## Data model

Coordinates are decimal feet. The origin is the southwest corner of the full footprint. +x is east, +y is north.

Wall `start` and `end` are centerlines. `thickness` is centered on that segment. Corners are butt joints: one wall runs through, the other stops at its face.

Each wall has an `assemblyId`. The app copies `thickness`, `assembly` (the render bucket), and `role` from `data/assemblies.json`. Do not ask the user to type a thickness. The render buckets are still:

- `rammed-earth` — south exterior walls, 1.5 ft (18 in). Wall-infill layer. No studs in the current assembly.
- `hempcrete` — other exterior walls, 1.0 ft (12 in), with a placeholder 2x6 at 24 in o.c. Wall-infill layer, studs on the framing layer.
- `framed` — interior partitions, 0.5 ft (6 in), placeholder 2x4 at 16 in o.c. Framing layer.
- `timber-infill` — earth infill between timber posts, 0.67 ft (8 in). `brick` — fired brick, 1.0 ft. `screen` — sliding paper screens, 0.17 ft. Wall-infill layer. These came with the templates.

Every assembly `note` must contain `placeholder: needs engineer/code verification` until a real source is cited. `source` stays `null` until then. Do not invent a code citation to fill it.

`phase` is `phase1` or `future`. Rooms are floor polygons. Areas in the UI are the shoelace area. After a wall edit, `syncRooms` in `src/build/rooms.js` rebuilds enclosed faces and keeps the old name and phase when the centroid still matches. Open areas such as the patio stay until someone deletes them, because they are not a closed loop.

Openings sit on a wall. `offset` is feet from the wall's start to the near jamb. A door or window must clear the corner by the placeholder distance in `data/headers.json` (6 inches) and must not overlap another opening. Each opening stores a `header` from that same table. `header.placeholder` is `true`, and the note repeats the placeholder marker. The framing layer draws studs, king studs, jack studs, and that header. Those sizes are not engineered.

A wall end always clicks onto another wall end within about 10 screen pixels, even with snap off. Moving a whole wall, or a group of selected walls (box-select, or drag a room to move its walls), snaps the same way: the move shifts so a moving end meets a still wall's end (`snapTranslation` in `src/build/snap.js`, `translateWalls` in `src/build/walls.js`). With Snap on, an end can also land on the middle of a wall, and `resolveJunctions` makes the tee on drop. Pressing on an item inside a multi-selection keeps the selection, so the drag moves it all; a plain click there selects just that item.

Doors and windows can be dragged onto a different wall: near another wall they jump to the clear spot nearest the pointer, otherwise they slide along their own wall. Copy and Paste (⌘C / ⌘V, Ctrl on Windows) work for doors, windows, scale figures, labels, and site marks, and for rooms and walls (see Arranging). The clipboard is in memory only. Paste lands at the pointer; a door or window lands on the clear wall nearest the pointer and is skipped if there is none. With Snap to grid on (or Shift held), wall ends also snap to the grid, to the middle of a wall, and to 0/45/90 degrees. With Clip on, a new wall that tees into or crosses another wall splits it; with Lay on (the default) nothing is cut and room detection still sees the tee. Collinear overlaps are refused. Geometry warnings go through `src/rules/` and draw a red dashed outline. They are not code checks.

The roof is placeholder massing: one roof per building in one of four forms (see Templates). `roof.placeholder` stays `true` until someone designs a real roof. Do not present it as structure.

## Proportions

`data/ratios.json` is the ratio library (golden, silver, roots, bronze, plastic, and the musical ratios). Exact forms are evaluated in `src/build/ratios.js`. Custom ratios live on the house as `customRatios`.

`constraints` on the house record `target`, `reference`, `ratioId`, and `operation` (`multiply` or `divide`). `src/build/constraints.js` solves them. The wall card no longer offers linking a wall's length to another wall (it picked walls by internal id and nobody could follow it). Locks already saved in a plan still solve, but changing a locked wall's length yourself (drag, type, snap, tidy) releases its lock in `commit` (`releaseEditedLocks`) instead of the solver snapping the wall back; the toast says which lock was released. A lock whose reference wall changes stays, and the locked wall follows. The wall card shows "Length lock" rows (locked to, or walls that follow this one) with Unlock. The room card's **Shape** chips call `snapRoomToRatio`, which tries every side of the room and each way to reach the ratio (stretch or shrink width or depth), corrects the move over a few passes because the room outline is recomputed, rejects results that merge or lose rooms, and keeps the smallest move. A cycle or two constraints on one target produces a warning and does not move those lengths. Wall constraints run after each edit. The sample footprint constraint (`width = φ × depth`) is stored so it is visible on first open. It is not applied, because 76 / 47 is about 0.06% short of φ and the drawn walls stay put. The plan shows the deviation instead of hiding it. (The old "Snap φ" button was removed: it changed only the footprint number, not the walls.)

Construction dimensions display to the nearest 1/16 inch. When that rounding is not the stored length, the label also shows the exact decimal. Stored coordinates stay the full float. **Stage 11 blueprint export must use these constrained float lengths, not the 1/16 inch construction rounding.** The rounding is only a label.

Proportions while drawing live in `src/build/shapeTools.js` and the tool options:

- **Room tool → Shape** (Free, Square, φ, √2, 3:2, 4:3, 16:9). With a shape picked, the dragged room keeps that width : depth measured inside the walls, using each side's wall thickness. The long side follows the cursor. The live label shows the shape and the inside size. A room drawn against an existing wall reuses that wall, so its inside size can be a little off the ratio.
- **Wall tool → Length from the wall you start on** (Free, Same, φ, √2, 3:2, 4:3, 2:1). A wall started on another wall's end is that wall × the ratio or ÷ the ratio, whichever is nearer the cursor. If several walls end there, the newest one is the reference. Started anywhere else, the wall is free and the label says to start on a wall end.
- These choices are per session, like the wall type. They do not change the house file.

`snapToRatioLength` in `src/build/ratios.js` (the old module × ratioⁿ ladder) is no longer wired to the tools. `proportion.module` and `proportion.ratioId` stay in the schema for old files.

## Conventions

- The JSON model is the source of truth. If a dimension is on screen, it comes from the model.
- Keep the sample flag and the on-screen "not a final design" label until James and Sophie decide a layout is theirs.
- **Every cost or code number must cite a source with a URL and the date it was checked. Never invent prices.** Do not add a dollar amount, a wage, a permit fee, or a code limit that you cannot point at. The model checker rejects keys that look like prices. Assembly thicknesses and header sizes are placeholders, marked in the data files, until that citation exists.
- A code citation names the rule and the adoption: 2021 IRC (WAC 51-51), 2021 WSEC-R (WAC 51-11R), 2023 NEC via L&I (WAC 296-46B), 2021 UPC (WAC 51-56). Quote the section. If the section number was not confirmed in the text, set `confirmSection` instead of guessing. Do not invent a price.
- Prefer a small module over a new framework. Other assistants will edit this repo.
- Do not add accounts, a database, or a server for a feature that can stay static.
- Wall and room geometry belong in `data/`, not in the renderers.
- **Speed:** every edit makes a new house object, so `areaReport`, `costReport`, and `evaluateRules` cache their answers per house object in a WeakMap. Never change a house in place after it has been published, or these return stale answers. The 3D view draws only when something changed (`needsRender`), draws nothing while hidden, and rebuilds the model at most every 180 ms during drags (`staleHouse`, `flushStale`). Call `requestRender`-style API methods, not `renderer.render`, from new code.

## How to add a new layer

1. Add an entry to `LAYER_DEFS` in `src/layers.js`. Use `stub: true` only if the layer should appear but draw nothing yet.
2. `defaultViewState()` in `src/state/viewState.js` picks up the new id automatically. Non-stub layers default on.
3. In `src/render/view3d.js`, a group with that id already exists if the id is in `LAYER_DEFS` (groups are created from the registry). Put meshes in `buckets[id]`, or in `futureBuckets[id]` when the geometry is part of a later wing.
4. In `src/render/plan2d.js`, draw the geometry only when `state.layers[id]` is on, and only when `isPhaseVisible` allows it.
5. If the geometry is part of the house, add it to `data/sample-house.json` and to `schemas/house.schema.json`. Then extend `scripts/check-model.mjs` so a bad file fails `npm test`.
6. Do not invent quantities for site. Plumbing quantities come from the placed fixtures and the rules in `src/plumbing/design.js`. A new price still needs a source, a URL when it has an amount, and a date.

## How to add an electrical device or rule

1. Add the kind to `DEVICE_DEFAULTS` or `APPLIANCES` in `src/electrical/design.js`, and to `PLACE_OPTIONS` so Build mode can place it. An appliance sets volts and amps. `gaugeForAmps` then picks the wire.
2. If it needs its own circuit, teach `buildElectrical` where that kind belongs. Dedicated 240V loads are already one circuit each. Kitchen, bathroom, and laundry receptacles are grouped before the general circuits.
3. Add a price id in `electricalBom` and a matching record in `data/prices.json`. If you cannot find a published price, set `amount` to `null` and `sourceName` to `Price needed`. Do not invent a dollar amount.
4. A code rule belongs in `src/rules/code.js`, not a second warning list. Give it an id, a short title, a one-sentence why, a citation, and a severity of blocker, warning, or tip. Add a test in `scripts/test-rules.mjs`. `deviceWarnings` remains for the older inline check. The plan and the header read `evaluateRules`.

## How to add a plumbing fixture or rule

1. Add the kind to `FIXTURES` and `PLACE_OPTIONS` in `src/plumbing/design.js`. Set the private DFU and minimum trap from UPC Table 702.1, and the supply fixture units from Table 610.3. If a cell is not confirmed, say so on the rule instead of inventing a number.
2. `buildPlumbing` routes supply from the water entry (hot from the water heater) and drains to a wet-wall stack, then to the septic stub. A new fixture is picked up if it is in `FIXTURES`.
3. Add a price id in `plumbingBom` and a matching record in `data/prices.json`. If you cannot find a published price, set `amount` to `null` and `sourceName` to `Price needed`.
4. A plumbing rule belongs in `src/rules/code.js` with the UPC section and the WAC 51-56 adoption URL. Mark `confirmSection` when the section number was not confirmed. `fixtureWarnings` remains for the older inline check.
